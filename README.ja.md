## 🧭 Site Sync とは?

**Site Sync** は **Visual Studio Code** の拡張機能で、**すでにオンラインで公開されているWebサイトをローカルで編集**できるようにします。

サイトのアドレスを入力すると、Site Sync は次のことを行います。

1. VS Code に内蔵された**プレビューでサイトを開きます**。
2. サイトが実際に使用しているファイル(スタイル、スクリプト、画像、フォント、ページなど)を**お使いのコンピューターに取得します**。
3. リモート版の代わりに**ローカル版を表示します**。
4. 変更を保存するとすぐに**プレビューをリアルタイムで更新します**。

公開中のサイトには**一切触れません**。すべてはあなたのコンピューター上の、あなたのプレビュー内で行われます。

```text
リモートサイト  →  ファイルを取得  →  ローカルファイル
                                          ↓
            プレビューがリアルタイムで更新  ←  VS Code で編集
```

## 💡 何に使えるの?

Site Sync は、**元のソースコードにアクセスできない既存サイトで、見た目や内容の変更を試したい**場面のために作られています。

- 🎨 実際のサイトで**新しいデザインを試す**(色、ダークテーマ、フォント、余白など)。
- 🧪 クライアントやチームに提案する前に**変更のプロトタイプを作る**。
- 🔍 エディターでファイルを見ながら**サイトの作りを理解する**。
- 🛠️ 複数の解決策をリアルタイムで試して**表示の不具合を直す**。
- 📚 実際のサイトを編集し、すぐに結果を見ながら**Web開発を学ぶ**。
- 🖼️ 実在のサイトから**スクリーンショットやモックアップを準備する**。

変更は**ローカルにとどまります**。表示されるのはあなたのプレビューの中だけです。

## 📥 インストール

### VS Code から(推奨)

1. VS Code を開きます。
2. **拡張機能**パネルを開きます(`Ctrl + Shift + X`、Mac は `Cmd + Shift + X`)。
3. **「Site Sync」** を検索します(発行者: *BunnyWhite*)。
4. **インストール**をクリックします。

### Marketplace から

拡張機能のページ <https://marketplace.visualstudio.com/items?itemName=BunnyWhite.site-sync> を開き、**Install** をクリックします。

### 必要条件

- **Visual Studio Code 1.85** 以降。
- VS Code で**開いているフォルダー**: Site Sync はここにサイトのファイルを保存します。
- 初回にサイトを取得するための**インターネット接続**。

## 🚀 5分で始める

**1. 作業用フォルダーを開く**
VS Code で *ファイル › フォルダーを開く*。空の新しいフォルダーを作っても構いません。

**2. Site Sync を開く**
アクティビティバー(VS Code の左側の縦のバー)にある **Site Sync** アイコンをクリックします。

**3. サイトのアドレスを入力する**
たとえば `https://example.com`。`example.com` とだけ入力しても、`https://` が自動的に追加されます。パス付きのアドレス(`https://example.com/products`)を入力すると、そのページが最初に開きます。

**4. 「開始」をクリックする**
サイトがプレビューで開きます。サイトが使用するファイルが、作業用フォルダーに少しずつ取得されます。

**5. ファイルを開いて編集する**
**リソース**ビューで、たとえばCSSファイルをクリックします。

**6. 保存する(`Ctrl + S`)**
変更がプレビューに反映されます。🎉

> 💡 初回起動時には**はじめにガイド**が自動的に表示されます。*Site Sync: Open Getting Started* コマンドでいつでも開き直せます。

## 🖥️ インターフェースの紹介

Site Sync は、VS Code のアクティビティバーに専用のセクションを追加します。2つのビューで構成されています。

### 「セッション」ビュー

拡張機能のダッシュボードです。

| 項目 | 役割 |
|---|---|
| **サイトURL** | 使用するサイトのアドレスを入力する欄 |
| **開始 / 停止** | セッションを開始・停止します |
| **セッション** | 状態を表示します: *停止中*、*開始中…*、*接続中* |
| **現在のページ** | プレビューに表示されているページ |
| **リソース** | 取得したファイルの数と、あなたが変更した数 |
| **操作** | クイックボタン: サイトを開く、ページのHTMLを編集、ファイルを開く、更新、停止 |
| **ヘルプ** | ドキュメントとはじめにガイドへのアクセス |
| **言語** | インターフェースの言語を変更するセレクター |

### 「リソース」ビュー

取得したすべてのファイルを、**種類別**に一覧表示するツリーです。

- **HTML**: 訪問したページ
- **CSS**: スタイルシート
- **JavaScript**: スクリプト
- **画像**: 画像とアイコン
- **フォント**: フォントファイル
- **その他**: それ以外(データ、メディアなど)

ファイルを**クリック**するだけでエディターで開きます。変更したファイルには印が付きます。

### プレビュー

プレビューは VS Code 内蔵のブラウザー(*Simple Browser*)です。**あなたの変更を反映した**サイトを表示します。外部ブラウザーを使うこともできます([設定](#-設定)を参照)。

## ✏️ サイトを編集する

### 🎨 CSS を編集する(外観)

スタイルシートは、色、フォント、余白などを変更するのに最適な場所です。

1. **リソース**ビューからCSSファイルを開きます。
2. 編集します。
3. 保存します(`Ctrl + S`)。
4. **ページを再読み込みせず、プレビューがすぐに更新されます**。スクロール位置やページの状態は保たれます。

> ℹ️ スタイルシートが特殊な方法で組み込まれている場合(別のスタイルシートからのインポート、ページ内への直接記述など)は、その場で更新する代わりに、プレビューが**ページを再読み込み**します。これは正常な動作です。

### 📄 HTML を編集する(内容と構造)

訪問した各ページは、作業用フォルダーに保存されます。

- セッションビューで**「ページのHTMLを編集」**をクリックする(または *Site Sync: Open Page HTML* コマンドを実行する)と、表示中のページのファイルが開きます。
- 編集して保存すると、ページが**再読み込み**され、あなたの版が表示されます。

| サイトのアドレス | ローカルファイル |
|---|---|
| `/` | `site/index.html` |
| `/products` | `site/products/index.html` |
| `/products/123` | `site/products/123/index.html` |
| `/about.html` | `site/about.html` |

**知っておくと便利なこと:**

- **変更していない**ページは、常に「ライブ」のままです。実際のサイトから配信されます(最新の内容、サインイン済みのセッションなど)。
- ページを**あなたが変更した**時点から、**あなたの版**が表示されます。そのページは**固定**され、動的な内容(データ、表示されるサインイン状態など)は更新されなくなります。モックアップの確認には最適ですが、個人向けにカスタマイズされたページでは注意してください。
- 元のページに戻すには、そのページの**ローカルファイルを削除**してください。再び取得されます。

### ⚡ JavaScript を編集する(動作)

1. **リソース**ビューからJavaScriptファイルを開きます。
2. 編集して保存します。
3. 変更を反映するため、ページが**完全に再読み込み**されます。

完全な再読み込みは意図的な仕様です。どのサイトでも、変更したスクリプトを確実に反映できる唯一の方法だからです。

### 🖼️ 画像やフォントなどを差し替える

作業用フォルダー内のファイルを、**同じ名前・同じ場所**のまま置き換えるだけです。Site Sync がそれを採用し、元のファイルの代わりに表示します。

### ➕ 独自のファイルを追加する

`site/` フォルダーの**正しいパス**にあなたが置いたファイルは、自動的に認識され、リモート版の代わりに配信されます。

## 🌐 ページ移動と新しいリソース

実際のサイトと同じように、プレビューで普通に移動してください。

- 新しいページを開くたびに、**現在のページ**の行が更新されます。
- ページに必要で、まだ手元にないファイルは**自動的に取得**されます。
- **すでにあるファイルは、再ダウンロードも上書きもされません**。
- ファイルを削除すると、次に必要になったときに再び取得されます。

### スマートなファイル検出

Site Sync は、ブラウザーが要求するのを待ちません。**ページを読み取り、使用されているファイルを見つけ**(スタイル、スクリプト、画像、フォント、アイコンなど)、実際に存在するか確認し、先回りして取得します。検出はさらに進み、**別のファイルから呼び出されるファイル**(たとえばスタイルシートが呼び出す画像やフォント)も追跡します。

ファイルが見つからない場合(404エラー)は、ログに記録され、**何も保存されません**。存在しないファイルの代わりにエラーページを返すサイト(「ソフト404」)も検出し、保存しません。

### 取得されるもの

| 種類 | 例 |
|---|---|
| HTMLページ | 訪問した**あなたのサイト**のページ |
| スタイル | `.css` |
| スクリプト | `.js`、JavaScript モジュール |
| 画像 | png、jpg、gif、svg、webp、avif、ico など |
| フォント | woff、woff2、ttf、otf、eot |
| データ | `.json`、`.webmanifest` |
| その他 | xml、txt、音声、動画など |

**動的な応答**(たとえばサイトがオンラインのサービスから読み込むデータ)は保存**されません**。固定するとサイトが壊れてしまうためです。

### 別の場所でホストされているファイル(CDN)

他のドメインでホストされているリソースは、`external` フォルダーに別途保存されます。

```text
https://cdn.example.com/library.js  →  site/external/cdn.example.com/library.js
```

### パラメーター付きのアドレス

`app.css?v=123` と `app.css?v=456` は**同じローカルファイル**(`app.css`)を指します。`?` 以降は、ファイル名の決定に使われません。

## 🔄 更新と競合の処理

作業中に、公開中のサイトが変更されることがあります。**更新**ボタン(または *Site Sync: Refresh* コマンド)で、手元のファイルとサイトのファイルを比較します。

- あなたが**変更していない**ファイルは更新されます。
- あなたが変更し、**かつ**サイト側でも変更されたファイルは**競合**になります。

> 🛡️ **大原則: あなたが行った変更は、自動的に上書きされることはありません。**

競合が起きると、メッセージで3つの選択肢が提示されます。

| 選択肢 | 動作 |
|---|---|
| **自分の版を保持** | あなたのファイルが保持されます。リモート版は記憶され、再び尋ねられることはありません。 |
| **リモート版をダウンロード** | あなたのファイルがサイトのファイルに置き換えられます。 |
| **比較** | 差分を確認できる並列表示が開き、その後、もう一度確認されます。 |

メッセージを閉じても何も変わりません。競合は再び提示されます。

> ℹ️ HTMLは別扱いです。更新時ではなく、訪問のたびにサイトと比較されます。あるページをやり直したいときは、そのローカルファイルを削除してください。

### 停止と再開

**停止**するとセッションは終了しますが、**すべてのファイルは保持されます**。同じサイトを再び開始すると、前回の続きから再開できます。

## 🔐 サインインとユーザーアカウント

Site Sync は、パスワード、Cookie、トークンを**一切要求せず**、**何も保存しません**。サイトへのサインインは、一般的なWebサイトと同じように**プレビュー内で直接**行ってください。

| 状況 | 動作 |
|---|---|
| フォームによるサインイン(ユーザー名/パスワード) | ✅ 通常は動作します |
| 二要素認証(2FA) | ✅ すべてがサイトのドメイン内で完結すれば動作します |
| 外部プロバイダーによるサインイン(Google、Microsoft、GitHub など / SSO) | ⚠️ 失敗することがあります。サイトへの戻りが拒否される場合があります |
| アクセス元に非常に厳しいサイト(ボット対策、クライアント証明書) | ❌ 動作しないことがあります |

**ヒント:** 起動のたびにサインインしたままにするには、設定(`siteSync.proxyPort`)で常に同じ**ポート**を使ってください。ポートが変わるとセッションは失われます。

アドレスにユーザー名とパスワードを含める形式(`https://user:password@site.com`)は**使用できません**。この形式は拒否されます。

## ⌨️ 利用できるコマンド

`Ctrl + Shift + P`(Mac は `Cmd + Shift + P`)でコマンドパレットを開き、「Site Sync」と入力します。

| コマンド | 動作 |
|---|---|
| **Site Sync: Start Website** | サイトのセッションを開始します |
| **Site Sync: Stop Website** | 現在のセッションを停止します |
| **Site Sync: Open Preview** | 現在のページでプレビューを(再)表示します |
| **Site Sync: Refresh** | 公開中のサイトと比較し、競合を処理して再読み込みします |
| **Site Sync: Open Website Folder** | サイトのファイルをエクスプローラーに表示します |
| **Site Sync: Open Page HTML** | 表示中のページのHTMLファイルを開きます |
| **Site Sync: Select Language** | 言語を変更します(English / Français / 日本語) |
| **Site Sync: Open Documentation** | 内蔵ドキュメントを開きます(オフラインで利用可能) |
| **Site Sync: Open Getting Started** | はじめにガイドを再表示します |

> コマンド名はパレットでは英語で表示されます。設定の説明は VS Code の表示言語に従います。

## ⚙️ 設定

*ファイル › ユーザー設定 › 設定*(または `Ctrl + ,`)を開き、**「Site Sync」** を検索します。

| 設定 | 既定値 | 説明 |
|---|---|---|
| `siteSync.language` | `en` | インターフェースとドキュメントの言語: `en`、`fr`、`ja` |
| `siteSync.showWelcome` | `true` | 初回起動時にはじめにガイドを表示します |
| `siteSync.previewTarget` | `simpleBrowser` | プレビューを開く場所: `simpleBrowser`(VS Code のブラウザー)または `external`(普段使うブラウザー) |
| `siteSync.proxyPort` | `4173` | ローカルで使用するポート。固定のポートを使うと**サインイン状態を保てます**。すでに使用中の場合は、別のポートが自動的に選ばれます。 |
| `siteSync.allowInsecureTls` | `false` | 無効なHTTPS証明書を許可します。テスト環境以外では**避けてください**。 |
| `siteSync.openPreviewOnStart` | `true` | 開始時にプレビューを自動的に開きます |

### プロジェクトごとの詳細設定

作業用フォルダーに `.vscode/site-sync.json` ファイルが作成されます。**秘密情報は含まれません**。次の項目を無効にできます。

| オプション | 効果 |
|---|---|
| `downloadHtml` | HTMLページを保存しなくなります |
| `downloadExternal` | 他のドメイン(CDN)でホストされるファイルを保存しなくなります |
| `prefetchReferenced` | ページ内で見つかったファイルの先回り取得を無効にします |

## 📁 ファイルはどこに保存される?

作業用フォルダーに、Site Sync は次を作成します。

```text
あなたのフォルダー/
├── .vscode/
│   ├── site-sync.json              ← 設定(秘密情報なし)
│   └── site-sync-resources.json    ← 取得したファイルの一覧と状態
└── site/
    ├── index.html                  ← サイトのページ
    ├── assets/
    │   ├── css/
    │   ├── js/
    │   ├── images/
    │   └── fonts/
    └── external/
        └── cdn.example.com/…       ← 他のドメインでホストされるファイル
```

`site/` の構成は**オンラインのサイトの構成をそのまま再現**します。`https://example.com/assets/css/main.css` は `site/assets/css/main.css` になります。サイトのコピーを持っているかのように、フォルダーをたどれます。

## 🛡️ セキュリティとプライバシー

Site Sync は、いくつかの安全対策を備えて設計されています。

- 🔒 **すべてがお使いのコンピューター内にとどまります**: プレビューには、あなたのコンピューターからのみアクセスできます(ローカルアドレス `127.0.0.1`)。
- 📂 **書き込みの保護**: Site Sync は **`site/` フォルダー内にのみ書き込めます**。悪意あるアドレスによって、ディスク上の他の場所へ書き込ませることはできません。
- 🚫 **上書きなし**: 既存のファイルが自動的に上書きされることはありません。
- 🔑 **秘密情報は保存しません**: パスワード、Cookie、トークンのいずれも保存しません。
- 🍪 **Cookie の分離**: サイトの Cookie が外部ドメインに送信されることはありません。
- 🔐 **既定で厳格なHTTPS**: 無効な証明書は拒否されます。
- 🌍 **特殊なスキームは不使用**: `http` と `https` のアドレスのみを使用します。

### ⚠️ 注意点

- **`site/` フォルダーは、内容を確認せずに公開しないでください。** 保存されたページやファイルには、**あなたのセッション**に関わる情報(名前、セキュリティトークン、技術的なキーやアドレス)が含まれることがあります。確認せずに公開リポジトリ(GitHub など)に置かないでください。
- **プレビューでは、サイトの保護機能の一部が取り除かれます**(コンテンツセキュリティポリシー、ファイルの整合性チェック)。そうしないと、変更したファイルがブロックされてしまうためです。これらの保護が外れるのは**プレビュー内のみ**で、あなたのファイルには影響しません。
- **サイトのスクリプトは、実際のサイトと同じようにプレビュー内で実行されます。** Site Sync はそれらを解析しません。**信頼できるサイトだけを使用してください**。

---

## ⚠️ 既知の制限

Site Sync は、すべてのサイトで完全に動作するわけではありません。知っておいていただきたい点は次のとおりです。

- **JavaScript のその場での更新はありません**: スクリプトを変更するたびにページが再読み込みされます(ページの状態は失われます)。
- **HTML は完全に再読み込み**されます。部分的な更新は行われません。
- ページの**アドレスのパラメーターは無視**されます: `/search?q=a` と `/search?q=b` は同じファイルを共有します。
- **サイトのリアルタイム接続**(WebSocket: チャット、ライブ通知など)は Site Sync を経由しません。
- **一部のサイトの「Service Worker」** は、Site Sync を経由せずにキャッシュされた版を表示することがあります。古い版が表示される場合は、ブラウザーの開発者ツールから無効にしてください。
- サイトが**動的に組み立てるアドレス**のファイル(特に別のドメインでホストされている場合)は置き換えられません。元の場所から直接読み込まれます。
- **サイト自身から見たアドレス**はローカルのプレビューのものになるため、アクセス元を確認するサイトでは問題が起きることがあります。
- **非対応のサイト**: 本来のアドレスを必要とするサイト(厳格な外部サインイン、ボット対策、クライアント証明書など)は動作しない場合があります。
- **バックグラウンドで読み込まれるページの断片**は保存されません(完全なページと埋め込みフレームのみ)。
- **変更したページは固定されます**: 動的な内容は更新されなくなります。

冒頭にも記載したとおり、この拡張機能は**実験的で、実際の環境で十分にテストされていません**。予期しない動作が起きる可能性があります。

## 🧰 トラブルシューティング

各セッションの技術的な詳細は、**出力 › Site Sync** パネルに記録されます(*表示 › 出力* メニューを開き、一覧から「Site Sync」を選択)。

| 問題 | 考えられる原因 / 対処法 |
|---|---|
| *「先にフォルダーを開いてください」* | Site Sync はファイルをフォルダーに保存します: *ファイル › フォルダーを開く* を実行してください |
| *「接続が拒否されました」* | サイトに到達できないか、アドレスが間違っています |
| *「ドメイン名が見つかりません」* | アドレスのスペルを確認してください |
| *「サーバーが時間内に応答しませんでした」* | サイトが遅いか停止しています。後でもう一度お試しください |
| *「HTTPS 証明書が無効です」* | 自己署名証明書または期限切れです。信頼できるサイトなら `siteSync.allowInsecureTls` を有効にしてください |
| CSS の変更が反映されない | ファイルが `site/` 内の正しいパスにあるか、*リソース*ビューに表示されているか、*Service Worker* がキャッシュされたコピーを配信していないか確認してください |
| JavaScript でページ全体が再読み込みされる | 正常な動作です。スクリプトにはその場での更新がありません |
| 白いページ、またはサイトが壊れる | サイトがリアルタイム接続、外部サインイン、特定のアドレスに依存している可能性があります。ログを確認してください |
| 起動のたびにサインアウトされる | ポートが変わっています: `siteSync.proxyPort` を固定してください |
| CDN のファイルが置き換わらない | サイトがアドレスを動的に組み立てています([既知の制限](#-既知の制限)を参照) |
| リソースが取得されない(HTTP 404) | サイト上に存在しません。情報はログにあります |
| インターフェースの言語が違う | サイドバーの*言語*セレクターまたは `siteSync.language` を使用してください |
| ファイルの書き込みエラー | ファイルとフォルダーが同じ名前です(たとえば `/a` と `/a/b.css`) |
| 変更したページが更新されない | 正常です。固定されています。ローカルファイルを削除すると再取得されます |

## ❓ よくある質問

**実際のサイトを変更してしまいますか?**
いいえ。すべての変更はあなたのコンピューターにとどまり、あなたのプレビューでのみ表示されます。Site Sync は、公開中のサイトに変更を送信できません。

**サイトのソースコードへのアクセスは必要ですか?**
いいえ。それこそがこの拡張機能の目的です。Site Sync は、ブラウザーが受け取るのと同じ形でファイルを取得します。

**オフラインで使えますか?**
初回の起動では使えません。サイトを取得する必要があるためです。ただし、内蔵ドキュメントはオフラインで利用できます。一度取得したファイルは、ディスクに残ります。

**パスワードで保護されたサイトでも動作しますか?**
ほとんどの場合、動作します。プレビュー内でサインインしてください。[サインインとユーザーアカウント](#-サインインとユーザーアカウント)を参照してください。

**自分のものではないサイトでも使えますか?**
技術的には可能ですが、[責任ある利用](#-責任ある利用)の項目をお読みください。

**変更は保存されますか?**
はい。`site/` フォルダー内の通常のファイルです。他のプロジェクトと同じようにバックアップやバージョン管理ができます(共有する前に内容を確認してください。[セキュリティ](#-セキュリティとプライバシー)を参照)。

**変更を実際のサイトに反映できますか?**
Site Sync はそれを行いません。変更を**準備してテストする**ためのツールです。その後、元のプロジェクトにご自身で反映してください。

**削除したファイルが戻ってくるのはなぜですか?**
サイトがそのファイルを再び必要としているためです。Site Sync は次の要求時に取得します。

**拡張機能は私のデータを収集しますか?**
いいえ。Site Sync はパスワード、Cookie、トークンを要求も保存もせず、ローカルでのみ動作します。
