# JavaScript

## JSの場所
```
https://example.com/assets/js/app.js   →   site/assets/js/app.js
```
ES モジュール(`import`)、動的 `import()`、挿入されたスクリプト、`fetch`/XHR リクエストはプロキシを通ります。自ドメインを指している場合は傍受され、ローカル版に置き換えられます。

## JSを編集する
編集して保存すると、Site Sync が変更を検出し、プレビューの**ページを再読み込み**します。

## 再読み込み
任意のサイトで**確実に動作**する仕組みは、ページ全体の再読み込みだけです。Site Sync は「ホットモジュール置換(HMR)」を意図的に模倣しません。スクリプトを動的に再評価すると、イベントリスナー、グローバル状態、副作用が重複してしまうためです。

## 制限事項
- HMR はありません: JS を変更するたびにページが再読み込みされます(ページの状態は失われます)。
- URL が JS 内で動的に組み立てられる**別ドメイン**のスクリプト(絶対URLで、HTML から観測できないもの)は書き換えられず、そのドメインから直接読み込まれます。
- サイトの *Service Worker* が、プロキシを通さずにキャッシュ済みリソースを返すことがあります。古い版が表示される場合は無効にしてください(Application › Service Workers)。
- `integrity=`(SRI)と CSP の `<meta>`/ヘッダーは**プレビューでのみ**削除されます。そうしないと、変更したファイルがブロックされてしまうためです。
- `location.origin` を元のオリジンと比較するコードには、`http://127.0.0.1:PORT` が見えます。
- サイトの WebSocket はプロキシされません(直接接続されます)。
