# セキュリティ

## パス
リモートURLが書き込み先のパスを自由に決めることはありません。各セグメントはデコードされ、`.`/`..` である場合や `/`、`\`、NUL を含む場合(`%2e%2e`、`..%2f` を含む)は拒否されます。禁止文字は置換され、最終的なパスは **`site/` の内側**に収まっているか検証されます。ファイルは「決して上書きしない」モード(`wx`)で書き込まれます。

## ネットワーク
- プロキシは **127.0.0.1 のみ**で待ち受け、想定外の `Host` ヘッダーを拒否します(DNS リバインディング対策)。
- http/https 以外のスキームへのリクエストは送信されません。
- **無効な証明書**: 既定では拒否されます(テスト環境では `siteSync.allowInsecureTls`)。
- リダイレクト: プロキシ内で追従されます。**別ドメイン**への遷移(OAuth、決済)はプレビューの外に出ます。
- サイトの **Cookie は外部ドメイン(CDN)に送信されず**、サードパーティの Cookie も保持されません。

## シークレット
Site Sync は、パスワード、Cookie、トークンを**一切**要求・読み取り・保存しません。認証情報付きのURLは拒否されます。他のWebサイトと同様にプレビュー内でサインインします。セッションはブラウザー(`127.0.0.1` の Cookie)に保持されます。

> **注意** — ダウンロードしたリソースには、クライアント側のキーやURLなど機密情報が含まれることがあります。確認せずに `site/` を公開リポジトリに追加しないでください。

## HTMLのコピー
保存されたページには、セッションのデータ(氏名、CSRFトークンなど)が含まれることがあります。確認せずに `site/` を公開コミットしないでください。

## 信頼できないコンテンツ
サイトやそのサードパーティのスクリプトは、実際のサイトと同様にプレビュー内で実行されます。Site Sync はそれらを解析しません。信頼できるサイトのみ使用してください。CSP と `integrity` は、プレビューでのみ削除されます。

## 認証に関する制限
| 項目 | 動作 |
|---|---|
| フォームログイン、Cookie | 動作します(Cookie は `http://127.0.0.1` 向けに書き換え)。固定ポートでセッションが維持されます |
| OAuth / SSO | プロバイダーへのリダイレクトでプレビューの外に出ます。サイトのオリジンへの戻りは(登録済みのコールバックURLにより)失敗することがあります |
| 2FA | フローがサイトのドメイン内に留まる場合は動作します |
| `__Host-` / `Secure` Cookie | ローカルの http では `Secure` が削除されます。拒否するサイトもあります |
| CORS | サイトのオリジンへのリクエストはプロキシ内(同一オリジン)に戻されます |
| CSP | プレビューでは削除されます |
